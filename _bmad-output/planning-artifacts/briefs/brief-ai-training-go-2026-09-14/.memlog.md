- (decision) Project is a personal Go-learning monorepo (ai-training-go); each learning exercise lives under apps/<name>/, run via docker compose up [--build] <service>. First app: apps/tui_tcp_chat/
- (decision) v1 scope: both TCP server and client written in Go, minimal — no rooms, usernames only as the one extra feature beyond raw text messages
- (decision) TUI library chosen: Bubble Tea (Charm ecosystem)
- (decision) Primary learning goals in priority order: goroutines/channels, then the net package, then project structure/modules as a beginner (step by step, not all at once)
- (decision) Go and Docker are not yet installed/working locally — setting them up is itself part of the learning goal, not a pre-existing prerequisite
- (decision) No deadline — pace is casual/whenever-I-get-to-it
- (decision) Repo will be a local git repo bound to remote git@github.com:BYankulov/ai-training-go.git via SSH
- (decision) Brief structure adapted from default template: What This Is / Why / The App (v1 Scope) / Infrastructure / Success Criteria / What's Next — replaces standard Problem/Differentiation/Users sections since this is a personal learning brief, not a market-facing pitch
- (decision) Module layout: single root go.mod for the whole monorepo (not per-app modules) — simpler for a beginner, easy cross-app imports later
- (decision) v1 explicitly excludes (deferred to later versions, not rejected): message history/persistence, auth/TLS/encryption, reconnect/resilience handling
- (decision) Done criteria for v1: functional — 2+ TUI clients connect to the server over TCP, exchange messages with usernames shown, all launched via docker compose up
